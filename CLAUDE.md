# CLAUDE.md

Этот файл предоставляет руководство для Claude Code (claude.ai/code) при работе с кодом в этом репозитории.

## Обзор проекта

Это инструмент автоматизации на Python, который симулирует пользовательскую активность для предотвращения перехода компьютера в спящий режим и поддержания статуса "активен" в корпоративных системах. Программа автоматически генерирует ежедневные расписания с рабочими часами, перерывами (включая обед) и специальными расписаниями для пятницы. Она симулирует движения мыши, нажатия клавиш и клики с естественной рандомизацией и функциями безопасности, чтобы не мешать реальной активности пользователя.

## Архитектура проекта

### Основные модули

- **`activity_simulator/`** (пакетная структура): Полностью реорганизованный код в модульном формате. Ключевые компоненты:

  - **`main.py`** (точка входа): Главная функция запуска программы, обработка сигналов, инициализация
  - **`simulation/`** (пакет симуляции): Модульная структура движка симуляции:
    - **`state.py`**: Класс `SimulationState` для инкапсуляции глобального состояния, константы безопасности
    - **`logger.py`**: `BufferedLogger` для буферизованного логирования и функции логирования
    - **`time_checks.py`**: Функции проверки времени (`is_work_hours`, `is_break_time`, `is_after_work`)
    - **`actions.py`**: Функции выполнения действий (`random_mouse_move`, `random_arrow_press`, `mouse_click`, `ctrl_tab`, `safe_key_press`, `type_key_sequence`)
    - **`modes.py`**: Обработчики режимов всплесков активности (`execute_burst_activity`)
    - **`simulation.py`**: Главный цикл симуляции (`simulate_activity`, `show_stats`, `init_simulation`)
    - **`__init__.py`**: Экспорт публичного API пакета

  - **`listeners.py`** (обработчики событий): Слушатели pynput для отслеживания реальной активности пользователя:
    - `on_mouse_event()`: Обрабатывает движение мыши/тачпада
    - `on_keyboard_event()`: Обрабатывает нажатия клавиш
    - `on_mouse_click()`: Обрабатывает клики мыши/тачпада

  - **`config.py`** (управление конфигурацией): Загружает конфигурацию из `config.yaml` и управляет генерацией ежедневного расписания. Ключевые компоненты:
    - `DEFAULT_CONFIG`: Резервные настройки по умолчанию, используются если YAML недоступен
    - `load_yaml_config()`: Загружает конфигурацию из `config.yaml` с проверкой целостности
    - `generate_schedule()`: Создает случайное ежедневное расписание с рабочими часами, обедом, короткими перерывами
    - `load_or_create_config()`: Загружает существующую или создает новую ежедневную JSON-конфигурацию
    - Логика специального расписания для пятницы с более ранним окончанием работы
  - **`config.yaml`** (файл конфигурации, корневая директория): **Основной файл для конфигурирования программы**. Содержит все настройки симуляции с подробными комментариями на русском языке. Редактируется вручную для настройки программы.

  - **`utils.py`** (утилиты): Вспомогательные функции:
    - `lock_computer()`, `shutdown_computer()`: Функции блокировки/выключения
    - `parse_key_sequence()`: Парсинг последовательностей клавиш
    - `type_key_sequence()`: Ввод последовательностей клавиш

### Ключевые паттерны проектирования

1. **Централизованное управление состоянием**: Класс `SimulationState` инкапсулирует глобальное состояние, обеспечивая потокобезопасный доступ через свойства и методы
2. **Событийно-ориентированная архитектура**: Слушатели pynput обнаруживают реальную активность пользователя и обновляют `last_activity_time` через `get_state()`
3. **Модульная структура симуляции**: Движок симуляции разделен на логические модули (state, logger, time_checks, actions, modes, simulation)
4. **Конфигурационно-управляемое поведение**: Все параметры контролируются через JSON-файлы конфигурации
5. **Ежедневная генерация расписания**: Случайные, но реалистичные рабочие расписания с равномерным распределением перерывов
6. **Симуляция естественного поведения**: Треугольные распределения, кривые ease-in-out, случайные интервалы

### Генерация файлов

- **Файл основных настроек**: `config.yaml` в корневой директории (создается при первом запуске если отсутствует)
- **Ежедневные файлы конфигурации**: `activity_config_YYYYMMDD.json` (создается ежедневно на основе `config.yaml`)
- **Лог-файлы**: `activity_log_YYYYMMDD_HHMMSS.txt` (создается при каждом запуске)
- **Пакетный файл**: `activity.bat` (удобный лаунчер для Windows)

## Конфигурация и настройка

**Важно:** Основные настройки программы теперь хранятся в файле `activity_simulator/config.yaml`. Этот файл содержит все параметры симуляции с подробными комментариями на русском языке. Файл `config.py` по-прежнему содержит `DEFAULT_CONFIG` — словарь с настройками по умолчанию, который используется как резервный вариант если YAML файл недоступен или поврежден.

### Ключевые области конфигурации (в `config.yaml`)

1. **Параметры симуляции**: `min_idle_time`, `max_idle_time`, `min_action_interval`, `max_action_interval`
2. **Параметры движения мыши**: `max_mouse_range`, `smooth_move_duration`, `smooth_move_steps`
3. **Параметры клавиатуры**: `min_key_presses`, `max_key_presses`
4. **Включение/выключение типов действий**: `use_mouse_move`, `use_keyboard`, `use_mouse_click`, `natural_behavior`, `verbose_logging`
5. **Веса действий**: `action_weight_mouse_move`, `action_weight_keyboard`, `action_weight_ctrl_tab`, `action_weight_mouse_click`, `action_weight_safe_key`
6. **Расписание рабочего дня**: `work_start_min/max`, `work_end_min/max`, `friday_work_end_min/max`
7. **Перерывы**: `lunch_start_min`, `lunch_end_max`, `total_break_min/max`, `lunch_duration_min/max`
8. **Внерабочий режим**: `afterhours_mode` (`disabled`/`before_only`/`before_and_after`)
9. **Функции безопасности**: `exit_on_activity_after_work`, `lock_on_exit`, `shutdown_on_exit`, `show_shutdown_warning`
10. **Действия после обеда**: `after_lunch_action`, `after_lunch_sequence` (имя переменной окружения), `after_lunch_delay`

### Жизненный цикл файлов конфигурации
- **Исходные настройки** определяются в `config.yaml` (или `DEFAULT_CONFIG`, если YAML недоступен)
- Файлы конфигурации генерируются ежедневно с именем `activity_config_YYYYMMDD.json` на основе загруженной конфигурации
- Существующая конфигурация для текущей даты повторно используется при последующих запусках
- Ручные правки `config.yaml` требуют перезапуска программы (Ctrl+C, затем перезапуск)
- При отсутствии `config.yaml` программа создаст его автоматически с настройками по умолчанию

### Важные константы безопасности
- `MINIMUM_DELAY_AFTER_USER_ACTIVITY = 60` секунд (задано в `simulation/state.py`)
- `MAX_CONSECUTIVE_SAFE_KEYS = 4` (задано в `simulation/state.py`)
- Прерывание серий действий при обнаружении активности пользователя во время выполнения

## Навигация по кодовой базе

### Точки входа
- **Основная программа**: `activity_simulator` (как модуль Python) → функция `main()` в модуле `main.py`
- **Консольный скрипт**: `activity-simulator` (после установки пакета) → указывает на `activity_simulator.main:main`
- **Конфигурация**: `activity_simulator.config` (основной файл для настройки программы) → `load_or_create_config()` вызывается из `main.py`

### Ключевые компоненты состояния (в `simulation/state.py`)
- `SimulationState`: Класс, инкапсулирующий все глобальное состояние симуляции
  - `last_activity_time`: Временная метка последней реальной активности пользователя
  - `initial_mouse_position`: Позиция мыши при начале симуляции
  - `absolute_anchor_position`: Референсная точка для ограничений движения мыши
  - `is_simulating`: Флаг, указывающий, что симуляция активна
  - `is_performing_action`: Флаг, указывающий, что действие выполняется
  - `action_history`: История выполненных действий (deque)
  - `config`: Конфигурация программы
  - `schedule`: Расписание рабочего дня
- `get_state()`: Функция для получения глобального экземпляра `SimulationState`

### Обработчики событий (в `listeners.py`)
- `on_mouse_event()`: Обрабатывает движение мыши/тачпада
- `on_keyboard_event()`: Обрабатывает нажатия клавиш
- `on_mouse_click()`: Обрабатывает клики мыши/тачпада

### Логика выбора действий (в `simulation/simulation.py`)
Расположена в функции `_handle_work_mode()`:
1. Создает взвешенный список действий на основе конфигурации
2. Случайный выбор на основе весов
3. Выполнение специфичных действий через модуль `actions.py`
4. Избегание 5 подряд нажатий безопасной клавиши (Shift)

## Работа с кодом

### При модификации логики симуляции
- Используйте `get_state()` для получения экземпляра `SimulationState`
- При доступе к общему состоянию используйте `state.lock` или контекстный менеджер `with state:`
- Проверяйте `state.is_performing_action` в обработчиках событий, чтобы избежать обратной связи
- Поддерживайте минимальную задержку `MINIMUM_DELAY_AFTER_USER_ACTIVITY` (60 секунд) после активности пользователя
- Обеспечьте возможность прерывания серий действий при обнаружении активности пользователя

### При модификации конфигурации
- Обновляйте `config.yaml` с подробными комментариями (или `DEFAULT_CONFIG` в `config.py` как резерв)
- Убедитесь, что `generate_schedule()` корректно обрабатывает новые параметры времени
- Тестируйте генерацию расписания с помощью `python -m activity_simulator.config`
- При добавлении новых параметров добавьте их в `DEFAULT_CONFIG` для обратной совместимости

### Советы по отладке
- Включите `verbose_logging: true` в конфиге для подробного логирования в файл
- Консоль показывает только сообщения ERROR/WARNING по дизайну
- Проверяйте ежедневные лог-файлы для деталей симуляции и статистики
