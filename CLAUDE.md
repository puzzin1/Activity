# CLAUDE.md

Этот файл предоставляет руководство для Claude Code (claude.ai/code) при работе с кодом в этом репозитории.

## Обзор проекта

Это инструмент автоматизации на Python, который симулирует пользовательскую активность для предотвращения перехода компьютера в спящий режим и поддержания статуса "активен" в корпоративных системах. Программа автоматически генерирует ежедневные расписания с рабочими часами, перерывами (включая обед) и специальными расписаниями для пятницы. Она симулирует движения мыши, нажатия клавиш и клики с естественной рандомизацией и функциями безопасности, чтобы не мешать реальной активности пользователя.

## Архитектура проекта

### Основные модули

- **`activity_simulator/`** (пакетная структура): Полностью реорганизованный код в модульном формате. Ключевые компоненты:

  - **`main.py`** (точка входа): Главная функция запуска программы, обработка сигналов, инициализация
  - **`simulation.py`** (движок симуляции): Содержит движок симуляции активности, обработчики событий мыши/клавиатуры, функции выполнения действий и главный цикл. Ключевые компоненты:
    - Глобальная блокировка (`global_lock`) для синхронизации потоков
    - Функции действий (`random_mouse_move`, `press_keyboard_keys`, `mouse_click`, `ctrl_tab`, `safe_key_press`)
    - Механизмы безопасности: минимальная задержка 60 секунд после активности пользователя, прерывание серий действий
    - Определение режима работы (`is_work_hours`, `is_break_time`, `is_after_work`)
    - Активность во внерабочее время с настраиваемыми интервалами

  - **`listeners.py`** (обработчики событий): Слушатели pynput для отслеживания реальной активности пользователя:
    - `on_mouse_event()`: Обрабатывает движение мыши/тачпада
    - `on_keyboard_event()`: Обрабатывает нажатия клавиш
    - `on_mouse_click()`: Обрабатывает клики мыши/тачпада

  - **`config.py`** (управление конфигурацией): Управляет конфигурацией и генерацией ежедневного расписания. Ключевые компоненты:
    - `DEFAULT_CONFIG`: Расширенные настройки по умолчанию с подробной документацией на русском языке
    - `generate_schedule()`: Создает случайное ежедневное расписание с рабочими часами, обедом, короткими перерывами
    - `load_or_create_config()`: Загружает существующую или создает новую ежедневную JSON-конфигурацию
    - Логика специального расписания для пятницы с более ранним окончанием работы

  - **`utils.py`** (утилиты): Вспомогательные функции:
    - `lock_computer()`, `shutdown_computer()`: Функции блокировки/выключения
    - `parse_key_sequence()`: Парсинг последовательностей клавиш
    - `type_key_sequence()`: Ввод последовательностей клавиш

### Ключевые паттерны проектирования

1. **Потокобезопасное глобальное состояние**: `global_lock` защищает общие переменные (`last_activity_time`, `is_simulating`, `is_performing_action`)
2. **Событийно-ориентированная архитектура**: Слушатели pynput обнаруживают реальную активность пользователя и обновляют `last_activity_time`
3. **Конфигурационно-управляемое поведение**: Все параметры контролируются через JSON-файлы конфигурации
4. **Ежедневная генерация расписания**: Случайные, но реалистичные рабочие расписания с равномерным распределением перерывов
5. **Симуляция естественного поведения**: Треугольные распределения, кривые ease-in-out, случайные интервалы

### Генерация файлов

- **Файлы конфигурации**: `activity_config_YYYYMMDD.json` (создается ежедневно)
- **Лог-файлы**: `activity_log_YYYYMMDD_HHMMSS.txt` (создается при каждом запуске)
- **Пакетный файл**: `activity.bat` (удобный лаунчер для Windows)

## Команды для разработки

### Установка и зависимости
```bash
# Установить зависимости (pynput для ввода, pydantic для конфигурации)
pip install pynput pydantic

# Установить пакет в режиме разработки (опционально)
pip install -e .
```

### Запуск программы
```bash
# Стандартный запуск (как модуль Python)
python -m activity_simulator.main

# После установки пакета можно использовать консольный скрипт
activity-simulator

# Удобный запуск в Windows (двойной клик)
activity.bat
```

### Тестирование модуля конфигурации
```bash
# Запуск config.py напрямую для тестирования генерации расписания
python -m activity_simulator.config
```

## Конфигурация и настройка

### Ключевые области конфигурации (в `DEFAULT_CONFIG`)

1. **Параметры симуляции**: `min_idle_time`, `max_idle_time`, `min_action_interval`, `max_action_interval`
2. **Веса действий**: `action_weight_mouse_move`, `action_weight_keyboard`, `action_weight_ctrl_tab` и т.д.
3. **Настройки расписания**: `work_start_min/max`, `work_end_min/max`, `friday_work_end_min/max`
4. **Внерабочий режим**: `afterhours_mode` (`disabled`/`before_only`/`before_and_after`)
5. **Функции безопасности**: `exit_on_activity_after_work`, `verbose_logging`

### Жизненный цикл файлов конфигурации
- Файлы конфигурации генерируются ежедневно с именем `activity_config_YYYYMMDD.json`
- Существующая конфигурация для текущей даты повторно используется при последующих запусках
- Ручные правки требуют перезапуска программы (Ctrl+C, затем перезапуск)

### Важные константы безопасности
- `MINIMUM_DELAY_AFTER_USER_ACTIVITY = 60` секунд (жестко задано в `simulation.py`)
- Прерывание серий действий при обнаружении активности пользователя во время выполнения

## Навигация по кодовой базе

### Точки входа
- **Основная программа**: `activity_simulator.main` → функция `main()` в модуле `main.py`
- **Консольный скрипт**: `activity-simulator` (после установки пакета) → указывает на `activity_simulator.main:main`
- **Конфигурация**: `activity_simulator.config` → `load_or_create_config()` вызывается из `main.py`

### Ключевые глобальные переменные (в `simulation.py`)
- `last_activity_time`: Временная метка последней реальной активности пользователя
- `initial_mouse_position`: Позиция мыши при начале симуляции
- `absolute_anchor_position`: Референсная точка для ограничений движения мыши
- `is_simulating`: Флаг, указывающий, что симуляция активна
- `is_performing_action`: Флаг, указывающий, что действие выполняется (защищено блокировкой)

### Обработчики событий (в `listeners.py`)
- `on_mouse_event()`: Обрабатывает движение мыши/тачпада
- `on_keyboard_event()`: Обрабатывает нажатия клавиш
- `on_mouse_click()`: Обрабатывает клики мыши/тачпада

### Логика выбора действий (в `simulation.py`)
Расположена в функции `perform_action()`:
1. Создает взвешенный список действий на основе конфигурации
2. Случайный выбор на основе весов
3. Выполнение специфичных действий с естественными задержками

## Работа с кодом

### При модификации логики симуляции
- Всегда используйте `global_lock` при доступе к общему состоянию
- Проверяйте флаг `is_performing_action` в обработчиках событий, чтобы избежать обратной связи
- Поддерживайте минимальную задержку 60 секунд после активности пользователя
- Обеспечьте возможность прерывания серий действий при обнаружении активности пользователя

### При модификации конфигурации
- Обновляйте `DEFAULT_CONFIG` в `config_manager.py` с подробными комментариями
- Убедитесь, что `generate_schedule()` корректно обрабатывает новые параметры времени
- Тестируйте генерацию расписания с помощью `python config_manager.py`

### Советы по отладке
- Включите `verbose_logging: true` в конфиге для подробного логирования в файл
- Консоль показывает только сообщения ERROR/WARNING по дизайну
- Проверяйте ежедневные лог-файлы для деталей симуляции и статистики
