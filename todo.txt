# Рефакторинг: замена глобального синглтона на параметризацию состояния

## Контекст

**Проблема:** Глобальный синглтон `_state` в `state.py` (строка 272) с функцией `get_state()` усложняет тестирование. Тесты вынуждены мокать `get_state()` и аккуратно сбрасывать состояние между тестами, что снижает надежность и поддерживаемость тестов.

**Текущее использование:** ~35 вызовов `get_state()` в 8 файлах кодовой базы. Все функции получают глобальный экземпляр состояния через эту функцию.

**Цель:** Заменить глобальный синглтон на передачу состояния через параметры (Dependency Injection), что упростит тестирование и улучшит архитектуру.

## Подход

Используем **гибридный подход** с сохранением обратной совместимости:

1. Функции принимают опциональный параметр `state: SimulationState = None`
2. Если `state` не передан, используется `get_state()` (backward compatibility)
3. В тестах создаются изолированные `SimulationState()` экземпляры

Это позволяет:
- Рефакторить код постепенно без ломающих изменений
- Тестировать функции в изоляции
- Сохранить работоспособность существующего кода

## План реализации

### Шаг 1: Обновить `state.py`
**Файл:** `src/activity_simulator/simulation/state.py`

- Добавить функцию `create_state()` для создания новых экземпляров
- Оставить `get_state()` для обратной совместимости
- Добавить docstring описывающий новый подход

```python
def create_state() -> SimulationState:
    """Создает новый экземпляр состояния для изолированного использования (например, в тестах)."""
    return SimulationState()
```

### Шаг 2: Обновить `simulation.py` функции
**Файл:** `src/activity_simulator/simulation/simulation.py`

Изменить следующие функции:
- `_handle_work_mode(state: Optional[SimulationState] = None)`
- `_handle_afterhours_burst(state: Optional[SimulationState] = None, ...)`
- `_handle_break_burst(state: Optional[SimulationState] = None, ...)`
- `_perform_light_action(state: Optional[SimulationState] = None)`
- `show_stats(state: Optional[SimulationState] = None)`

В каждой функции:
```python
if state is None:
    state = get_state()
```

### Шаг 9: Обновить тесты
**Файлы:**
- `tests/test_actions.py`
- `tests/test_listeners.py`
- `tests/test_modes.py`

Для каждой функции тестируемой с `state` параметром:
```python
state = create_state()
state.config = {...}

```

### Шаг 10: Обновить `main.py` для использования явного state
**Файл:** `src/activity_simulator/main.py`

Вместо:
```python
state = simulation.get_state()
```

Использовать:
```python
state = simulation.create_state()
state.set_config(cfg)
state.set_schedule(sched)
```

И передавать `state` явным образом в вызовы функций.

## Порядок выполнения

Рекомендуется следующий порядок:
1. `state.py` - создать `create_state()`
2. `actions.py` - обновить все функции
3. `time_checks.py` - обновить все функции
4. `modes.py`, `logger.py` - обновить функции
5. `simulation.py` - обновить основные функции
6. `listeners.py` - обновить функции
7. `main.py` - использовать новый подход
8. Тесты - обновить по одному модулю за раз
9. Запуск полного тест-сьюита

## Верификация

После реализации:

1. Запустить все тесты: `pytest tests/ -v`
2. Запустить программу: `python -m activity_simulator` - убедиться что работает
3. Проверить что старый код (использующий `get_state()`) всё ещё работает
4. Убедиться что тесты больше не используют моки `get_state()`, а создают реальные `SimulationState()`

## Примечания

- Изменения обратимо совместимы через параметр по умолчанию `state=None`
- Можно выполнять итеративно, по одному модулю за раз
- После полного перехода можно рассмотреть удаление `get_state()` в будущих версиях
- В документации (`CLAUDE.md`, `README.md`) нужно обновить примеры использования
